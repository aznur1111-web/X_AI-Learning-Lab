    Quick guide: Explainable AI (XAI)

    Explainable AI means methods that help people understand how an AI model arrived at a prediction: which input signals mattered, how the prediction changes, and where the explanation might be unreliable. It helps people inspect a model; it does not prove the model is correct, fair, or causal.

    SHAP in the simplest terms

    Think of the prediction as a bill split among the input features. SHAP assigns each feature a contribution relative to a baseline prediction. A positive value pushes the selected output above the baseline; a negative value pushes it below, subject to the explainer and output scale.

    Best fit: comparing feature contributions consistently for individual predictions and summarizing patterns across many cases.

    LIME in the simplest terms

    Imagine a small, simple map drawn around one house. LIME changes parts of one input, asks the complex model for its answers, then fits a simple local model to approximate the behavior nearby.

    Best fit: a quick, human-readable explanation for one case, especially when you need to inspect a black-box model locally.

    SHAP vs LIME

    • SHAP: baseline-relative feature contributions using Shapley-value ideas. Useful for local explanations and aggregate feature-importance analysis. Can be computationally expensive; results depend on explainer choice and background data.
    • LIME: a locally fitted interpretable approximation around one example. Often easier to explain as a short local story, but can change with sampling, neighborhood settings, and random seed.
    • Both: explain model behavior, not necessarily real-world causes. Test fidelity, stability, and whether the explanation makes sense for the domain.

    What tools are used for XAI?

    • Python foundations: pandas and NumPy for data, scikit-learn for models and inspection.
    • Tabular model explainers: SHAP, LIME, permutation importance, partial dependence (PDP), individual conditional expectation (ICE), and counterfactual tools such as DiCE.
    • Deep learning: Captum for PyTorch, Integrated Gradients, gradient/saliency methods, Grad-CAM for vision, and model-specific attribution tools.
    • Text and language models: token masking, SHAP text explainers, LIME text explainers, attention inspection (not automatically a faithful explanation), and evaluation/sanity checks.
    • Operational practice: notebooks, experiment tracking, model cards, dashboards, subgroup analysis, stability tests, and human/domain-expert review.

    Application fields and concrete examples

    • Healthcare: inspect whether a risk model relies on clinically meaningful measurements rather than hospital-specific shortcuts. A clinician must validate explanations.
    • Banking and insurance: examine factors associated with a credit-risk or claim prediction and test whether explanations are consistent and compliant. Attribution alone is not a legally sufficient decision reason.
    • Manufacturing: investigate whether a defect detector relies on the defect itself or on lighting, camera, or background artifacts.
    • Retail and marketing: inspect which customer/session features influence a churn or conversion prediction; check subgroups and drift.
    • Cybersecurity: investigate which traffic features drive an anomaly alert and whether the explanation reflects a real attack pattern or a benign proxy.
    • Computer vision: use saliency/Grad-CAM to inspect image regions influencing a classifier; test maps rather than trusting attractive heatmaps.
    • NLP and moderation: inspect words or phrases associated with a sentiment, spam, or moderation output; check masking artifacts and demographic bias.
    • Science and engineering: audit surrogate models, feature interactions, and model sensitivity in climate, materials, energy, or predictive-maintenance workflows.

    Python code cookbook

    These examples are intended for a local Python environment, not executed by this browser app. Install the libraries first with pip install scikit-learn shap lime matplotlib pandas. The code trains a small synthetic model so you can run it without downloading a dataset.

    1. Train a small model (shared setup)
    import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

X, y = make_classification(
    n_samples=500, n_features=5, n_informative=3,
    n_redundant=1, random_state=7
)
feature_names = ["feature_A", "feature_B", "feature_C",
                 "feature_D", "feature_E"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=7, stratify=y
)
model = RandomForestClassifier(n_estimators=100, random_state=7)
model.fit(X_train, y_train)

row = X_test[0:1]
print("Predicted class:", model.predict(row)[0])
print("Class probabilities:", model.predict_proba(row)[0])
    2. SHAP: explain one prediction
    import shap

# A small representative background sample establishes the baseline.
background = X_train[:80]
explainer = shap.TreeExplainer(model, data=background)
shap_values = explainer(row)

# Modern SHAP versions commonly return an Explanation object.
print("Base value:", explainer.expected_value)
print("Feature contributions:", shap_values.values)

shap.plots.waterfall(shap_values[0], max_display=5)
# For global patterns, summarize a representative test sample:
sample = X_test[:100]
shap_sample = explainer(sample)
shap.plots.beeswarm(shap_sample)
    Interpret the SHAP plot relative to its baseline and output scale. SHAP values are not causal effects. For binary classifiers, check the installed SHAP version's output shape and which class/output you are explaining.
    3. LIME: explain one prediction
    from lime.lime_tabular import LimeTabularExplainer

lime_explainer = LimeTabularExplainer(
    training_data=X_train,
    feature_names=feature_names,
    class_names=["class_0", "class_1"],
    mode="classification",
    discretize_continuous=True,
    random_state=7
)

explanation = lime_explainer.explain_instance(
    data_row=X_test[0],
    predict_fn=model.predict_proba,
    num_features=5,
    num_samples=3000
)
print(explanation.as_list())
# In a notebook, this renders a local explanation:
explanation.show_in_notebook(show_table=True)
    LIME describes a local approximation around this one row. Check its local fidelity and repeat with different random seeds or sample counts to see whether the explanation is stable.
    4. A simple model-independent baseline: permutation importance
    from sklearn.inspection import permutation_importance

result = permutation_importance(
    model, X_test, y_test,
    n_repeats=10, random_state=7, scoring="accuracy"
)
for i in result.importances_mean.argsort()[::-1]:
    print(feature_names[i], round(result.importances_mean[i], 3))

    Suggested beginner workflow

    1. Train and evaluate a baseline model before explaining it.
    2. Pick the question first: why this case (local), what matters overall (global), or what change could alter the outcome (counterfactual).
    3. Start with permutation importance or PDP for a broad view, then use SHAP or LIME for individual cases.
    4. Check representative examples, edge cases, subgroups, stability, and model performance.
    5. Write down the model version, data sample, explainer settings, output/class explained, limitations, and intended audience.
